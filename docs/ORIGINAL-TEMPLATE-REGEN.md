# AnPPT 原创模板与风格重制规范（三套首发）

> 状态：生成机制已落地。2026-08-22 已完成三套赛事首发原创位图并接入公开风格库；其余迁移期样张继续按本规范逐套原创生成、人工验收后原子切换。

## 目标与边界

AnPPT 要保留旧版生成效果好的部分：整套统一、信息清楚、真实文档保真、页面不机械重复；同时吸收已授权抖研前端中经过验证的产品方法：先识别赛事/业务场景，再选择叙事骨架和页型任务，用逐页同风格参考维持整套一致性。最终资产、命名、设计语言和提示词均由 AnPPT 自己维护。

可以参考：

- 赛事/行业 → 叙事骨架 → 页型序列的组织方式；
- page type aliases 对 LLM 自由文本做稳定归一；
- 大纲页与参考页逐页映射，而不是整套只给一张封面；
- 场景关键词、内容任务、布局任务和视觉设计分层表达；
- 逐页事件、恢复、重试和可编辑导出的交互方法。

禁止复制：

- 第三方成品预览图、原始 PPTX、CDN 地址或远程模板；
- 第三方 Logo、品牌名称、营销文案、设计师署名和水印；
- 某一套模板的固定 1:1 页面序列、具体装饰资产或受保护视觉表达；
- 原文没有的奖项、专利、政策、公章、人物、机构、Logo 和数据。

## 已落地的 AnPPT 自有生成链

1. **整套场景识别**：整套标题和有限原文信号参与受众、行业、赛事判断；不把原始材料全文直接塞进生图提示词。
2. **六类叙事骨架**：创新创业/挑战杯、技能教学/世校赛、职业规划、企业经营、政企/学校行政/工作单位、科研学术。页数不足时合并，原文无依据时省略，禁止机械补页。
3. **35 个页型任务**：覆盖封面、目录、章节、痛点、方案、技术、数据、案例、团队、教学、技能、政企、科研等；每个页型同时定义信息目标、布局约束和参考图类别。
4. **逐页同风格参考**：按 cover/toc/section/content/data/process 等类别，从同一风格包选择最匹配样张；整套不再只有封面带参考。
5. **原创设计 DNA**：28 个公开风格包各自维护色板、栅格、装饰母题、图形语言、质感、场景标签和禁用元素；稳定 `stylePackId` 与历史 `legacySlugs` 保持兼容。
6. **真实性与相关性闸门**：禁止通用 AI 大脑、机器人、随机粒子、无关城市与握手照；图片必须服务于本页论点，数据和证据必须来自用户材料。

## 共通硬约束

- 16:9，中文 `Noto Sans SC`，英文与数字 `Inter`；现阶段不依赖上游未明确支持的微软雅黑/方正字体。
- 页眉 Logo 图形、比例、颜色和坐标整套固定；未上传 Logo 时保留安全空框，模型不得臆造。
- 六类必备页面能力：封面、目录、章节、通用内容、数据、流程/时间轴；实际套稿是否出现由内容与骨架决定。
- 每张预览使用真实、代表性的学校/企业/工作单位场景内容，不能使用 lorem ipsum、测试包名称或第三方品牌标识。
- 赛事类优先采用评审熟悉的信息结构，但必须根据用户材料取舍，不硬凑“标准 26 页”。
- 生成验收：文字无乱码/错字、无假 Logo、无水印、无越界、图表口径一致、同套色板与装饰母题一致、正文在投屏尺寸可读。
- 易转可编辑：减少文字压图、复杂玻璃叠层、过细描边和无法分割的装饰；标题、正文、数据和图示保持清晰区域边界。

## A. 高校赛事 / 创新创业路演

- 受众：互联网+、挑战杯、教学能力比赛、创新创业项目、科研答辩。
- 气质：可信、年轻、有冲击力但不过度科幻。
- 色板：深海蓝、科技青、少量暖橙作为成果强调。
- 代表页面：项目痛点、创新方案、技术路线、竞品对比、商业模式、团队与成果、赛事答辩结束页。
- 数据页：大数字 + 证据来源 + 评审可快速扫读的结论条。
- 骨架检查：是否回答“为什么做、为谁做、怎么做、凭什么赢、证据是什么、谁来做、下一步是什么”。

## B. 企业商务 / 经营数据汇报

- 受众：经营分析、季度复盘、客户方案、融资路演、管理层汇报。
- 气质：克制、专业、结论先行。
- 色板：墨蓝/石墨灰，按行业允许青绿或橙色强调。
- 代表页面：经营总览、指标拆解、趋势图、问题归因、策略矩阵、里程碑、行动清单。
- 数据页：一个核心结论、最多三组辅助指标，不堆满装饰图表。
- 骨架检查：目标/结果/差距/原因/动作/责任/时间必须形成闭环。

## C. 政企 / 工作单位工作汇报

- 受众：政府、事业单位、国企、学校行政与工作总结。
- 气质：稳重、清晰、正式，避免娱乐化视觉。
- 色板：政务蓝、深红或墨绿的低饱和组合；大面积白底保证打印和投屏。
- 代表页面：年度重点、工作成效、政策依据、问题清单、推进机制、时间表、下一步安排。
- 页眉：单位标识区预留固定安全框；未上传 Logo 时保持空白，禁止模型臆造。
- 骨架检查：政策/任务来源、工作举措、量化成效、问题风险与下一步安排应可追溯。

## 2026-08-22 三套赛事首发批次

- 已公开 3 套 AnPPT 原创赛事风格：深海蓝创新赛事答辩风、精密制造技能竞赛风、暖橙职业成长答辩风。
- 共 18 张 WebP，统一为 1536×864；每套固定覆盖 `cover`、`toc`、`section`、`content`、`data`、`process` 六类页面。
- 图片由 `gpt-image-2` 原创生成；生成输入未使用第三方模板图、Logo、CDN、PPTX 或品牌文案。
- 每套 `manifest.json` 记录文件 SHA-256、生成模型、来源声明与 `passed-manual-visual-qc` 人工视觉审核状态。
- 生图提示词继续强制 Codia 友好边界：文字与照片分区、单页主要文本组不超过 5 个、避免复杂蒙版/多层透明/过细描边/跨区斜切文字。
- 回滚时仅移除 `src/data/style-packs.ts` 中三个 `anppt-original-*-20260822` 公开项及 `src/data/style-design-dna.ts` 对应 DNA，保留原 25 个公开包；静态资产先保留至少一个发布周期，禁止模糊删除。

## 资产生产、验收与原子替换

1. 每套先生成六种核心页型各 2 个候选，共 36 张候选图；候选写入独立版本目录，绝不覆盖线上资产。
2. 使用真实且脱敏的学校、企业、政企材料做 5/10/20 页 dry-run，验证短稿不会硬凑、长稿不会丢关键证据。
3. 人工按内容真实性、场景代表性、同套一致性、投屏可读性、可编辑友好度五项打分；任何假 Logo/假数据/错字直接淘汰。
4. 每类选出至少 6 张首发预览，并验证 cover/toc/section/content/data/process 的逐页参考映射不会错位。
5. 先在非公开 manifest 中登记新路径并跑资源完整性测试，再一次性切换 `previewUrl`/`previewImageUrls`；禁止半套新旧混用。
6. 上线后保留上一版本 manifest 和资源至少一个发布周期；若生成质量、历史 slug 或资源路径回归，立即回切旧 manifest。
7. 确认线上无旧版本引用后，再按明确清单清理旧资产；不得用模糊通配符删除整个风格目录。

## 发布闸门

- 28 个公开风格包 id 可解析，其中原 25 个历史 id 与 slug 保持兼容；测试目录不公开。
- 所有 manifest 引用文件存在，且浏览器可加载；不得把 base64 全量缓存进 Node 内存。
- 35 页型均有确定的信息任务和参考类别，通用标题仍能借整套上下文识别赛事/行业。
- 生成、后端、lint、类型检查与 build 全绿；桌面和移动端风格选择页无错位、溢出和第三方品牌残留。
- 资产来源、生成批次、审核人、切换时间和回滚 manifest 有记录；不通过则不替换。
