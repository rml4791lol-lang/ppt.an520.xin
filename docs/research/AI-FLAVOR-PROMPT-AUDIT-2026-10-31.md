# 「AI 味」成因调研 + 站内提示词改造对照

> 调研日期：2026-10-31
> 范围：AnPPT v2 全套提示词面（生图八段式 / 页型协议 / deck 蓝图 / 大纲文案）+ 风格包数据 + 样张资产
> 口径：可举证的论文、官方文档、模型厂商文档优先；社区帖只作为实测证据，不当结论。数字均为本机实测。

---

## 0. 结论先行

1. **「AI 味」不是配图陈词问题，是版式与用色的统计特征问题。** 站内提示词里已有的「禁用 AI 大脑/发光机器人」只挡住了一种陈词；真正被机器识别、被同行一眼看穿的是：居中 hero + 顶部小标签 + 三张等宽卡、全页只有一套字号、紫蓝渐变、全同圆角+软投影、零留白、每标题配 emoji、每页固定装饰 chrome。这些都可以量化，也都可以写进提示词。
2. **站内模板套本身就是最大的 AI 味源头。** 40 套样张首图实测：冷色相（195°–275°）占比中位数 **82.1%**，`>60%` 的 24/40、`>85%` 的 19/40；彩色像素平均饱和度 **0.60**，`>0.7` 的 16/40。39 套风格包的视觉关键词里 **20 套**含「渐变/光感/光效/玻璃/弥散/粒子/发光/霓虹/3D/磨砂」。
3. **否定式与数值各有分工（含模型实测修正）。** 2025 年社区结论是 gpt-image-1 / Imagen 4 / Nano Banana 静默忽略 negative prompt（FLUX 直接 400），因此初期方案是「禁令一律改正向锚点」。但项目负责人实测反馈：线上在用的 **image2.5（tt-image-2.5）对「不要哪些」理解得很好**，否定式清单仍是主骨架。故最终策略为三层：**否定式画法清单（骨架）+ 硬数字（校准）+ 人作痕迹许可（主观表达）**。
4. **文案「AI 腔」的本质是信息密度与判断密度为零，不是词表。** AI 天生避开可被反驳的断言，于是标题退化成 4-8 字名词短语，要点恒为 3-4 条 × 等长 12-16 字。只加词表治不了；必须加「结论句标题 + 条数不定 + 字数极差 + 每页必须带口径数字」这类**结构约束**。
5. **本轮已落地 8 个文件的改造并全绿。** 提示词可量化数值从 3 个增至 48 个；49 个光效类视觉关键词改写成可落笔形态词；页型协议新增「版式坐标」；蓝图四节从「氛围/光照」改为「底色层次/hex/栅格字号/渲染方式」。`node scripts/test-generation.mjs` **1039 通过 / 0 失败**；`npm run gate` **8 步全绿，25.4s，退出码 0**。
6. **两个真实残留**（不掩盖）：①39 套样张图片本身没有重绘，第 6 段仍把旧样张作为参考图喂给模型，「只提取色板/栅格/卡片边界」这句挡不住玻璃拟态被视觉复制；②大纲主链走外部引擎 `http://127.0.0.1:3002`，本仓库的 `OUTLINE_SYSTEM_PROMPT` 只在引擎不可达时兜底，文案纪律要真正生效还需引擎侧同步。

## 3. 视觉侧：AI 味的 12 个可举证特征

1. 居中 hero + 顶部 eyebrow 小标签 + 三张等宽卡（中文四源 + 英文 `ai_slide_tells` 独立同述；原话 *A row of identical boxes with different words in them is a list wearing a costume.*）
2. 紫蓝渐变当主色（anti-slop 称之为 "the AI startup gradient"；腾讯云把大面积渐变背景列为一票否决）
3. 所有卡片同半径圆角 + 软投影（mathmodel 令牌：圆角上限 10px；`ai_slide_tells`：软阴影是「generated UI 的默认外观」）
4. 零留白、信息过载（mikareyes：第一条判断依据就是 "There's no white space"）
5. 每个标题配 emoji 或圆角图标（三方一致）
6. 只用一套字体（anti-slop："Inter for everything"）
7. 玻璃拟态 / 弥散光 / 粒子 / 悬浮 3D
8. 版式不随内容变化（8 页同一个盒子）
9. 生成过程泄漏进成品：「本页介绍…」「综上所述…」
10. 每页固定装饰 chrome（被该文称为 **the single most-cited visual tell**）
11. 配图通用化（可原封不动换到任何行业）
12. 纯黑纯白 + 饱和度失衡

### 3.1 人类基准（可直接写进 prompt 的数值）

| 维度 | AI 默认 | 人类基准 |
|---|---|---|
| 栅格 | 无栅格 / 8px 机械均分 | 12 栏；页边距 ≥6% 短边 |
| 字阶 | 一套字号，差值 1.1–1.2× | 模数比 1.25–1.333，全页 ≤4 档 |
| 行高 | 1.2–1.4× | 1.6–1.75× |
| 行宽 | 满宽铺排 | 45–75 字符 / 中文 18–26 字 |
| 圆角 | 12–24px | 4/6/8，上限 10 |
| 色量 | 1 渐变 + 3 突出色 | 2 主色 + 1 中性阶；强调 ≤2 处 |
| 焦点 | 多个 | ≤2 个 |
| 最小字号 | 任意缩 | 8pt，低于此值拆页 |

### 3.2 为什么模型会「安全审美」（A 级）

- **训练目标错位**：LAION-5B 经 aesthetic predictor 过滤成 LAION-Aesthetics，成了 SD 系训练集——优化目标从「有效」变成「好看」（Caldas, *A matter of taste*）。
- **Polish 被误当质量**：偏好优化让模型倾向「看起来专业」，而评审的 cognitive-fluency 通道会把 polish 读成质量（HBS WP 26-094）。
- **同质化机制**：数据偏置 + 架构约束 + prompt 三重限制导致 design fixation（arXiv 2502.05870）。
- **廉价专业外观**：少量 prompt 即可产出「专业外观」（arXiv 2601.06060），于是用户不再追问信息是否成立。

### 3.3 模型方言（决定改写方式）

| 模型 | negative prompt | 图内文字上限 | 有效结构 |
|---|---|---|---|
| gpt-image-1（本站 `ANPPT_V2_IMAGE_MODEL` 默认族） | **静默忽略**，须改正向 | ~30 字符 | Subject→Context→Style→Constraints |
| Imagen 4 / Nano Banana | 忽略 | 10–20 字符 | 叙事散文 |
| SDXL | 有效（CFG） | 77 CLIP tokens | tag-soup + negative |
| FLUX | 直接 400 | 512 tokens | 长句散文 |

→ 本站默认模型属第一行：**写「不要渐变」= 白写，甚至反效果**。这条直接决定了本轮改造的写法：把「不靠发光」改写成「背景单一实色、层次用同色系三级明度、圆角 4-8px、分隔 1px 细线、平光无投影」。

## 4. 文案侧：AI 腔的判定与阈值

结论：**AI 味 = 低信息密度 + 低判断密度**，词表法不够（AI 中文的词汇熵反而更高，异常在结构与证据）。

可写死的阈值（B/C 级交叉，已写入 `OUTLINE_SYSTEM_PROMPT`）：

- 内容页标题 15-25 字结论句，含数字/对象/原因至少一项；章节页 ≤6 字；禁止 4-8 字名词短语标题。
- 要点 1-5 条，**全篇不得固定在 3 条或 4 条**；同页字数极差 ≥8 字；至少 1 条非动词开头。
- 每条含数字、专名、时间点之一；数字必须带基数/时间/口径中至少 2 项。
- 每页 ≥1 句 ≤10 字；单句 ≤35 字；三连排比 ≤2；每 3 页 ≥1 处取舍/风险/未验证。
- 套话配额：赋能/闭环/抓手/深耕/聚焦/助力/打造/引领/全方位/多维度/数智化/新质生产力/降本增效/提质增效/底层逻辑/顶层设计/一站式/沉浸式 —— 全篇 ≤1 次，且不得进入标题。

## 7. 残留问题与未验证

1. **样张图片未重绘。** 第 6 段仍随附一张旧样张并要求「只提取色板/栅格/卡片边界」。旧样张本身是玻璃拟态/高饱和冷蓝，模型有概率把观感一起复制。**根治要重绘 39 套样张首图**（或先用「弱参考」开关做 A/B）。
2. **文案纪律只在降级路径生效。** 大纲主链在外部引擎 `PPT_ENGINE_BASE_URL`（默认 `http://127.0.0.1:3002`），本仓库 `OUTLINE_SYSTEM_PROMPT` 是兜底。需要在引擎侧同步同一份 7 条纪律。
3. **未验证：视觉观感。** 本会话 `read_image` 始终返回「attachment service is unavailable」，无法对改造前后的出图做肉眼对照；本轮全部结论基于提示词文本、样张像素统计与测试，**没有跑真实生图**（会消耗上游额度，用户未点名）。
4. **未做 A/B。** 建议下一轮用同一大纲 + 同一风格包各出 1 页改造前/后，人工盲评，再决定是否把 `SLIDE_LAYOUT_SPEC` 扩到「强约束」（当前是可被判定的数值规范，不是 sanitizer）。
5. **风格包 name/slug 仍含「渐变」「磨砂玻璃」等字样。** 它们是对外公开 id / legacySlugs，受测试保护，不能随意改；若要做品牌层清理，需单独走迁移。

## 8. 下一步建议（按性价比排序）

1. 重绘 6 张高频风格包样张（深海蓝/深空/苹果式/NVIDIA式/医疗/测试包），验证「提示词 + 新样张」的组合效果。
2. 引擎侧同步文案纪律，或把大纲生成拉回本仓库，才谈得上端到端控制。
3. 出一版「强约束」开关：把 `SLIDE_LAYOUT_SPEC` 从建议段升级为后置校验（生成后按数值断言检查，不满足就重试一次）。
4. 观察线上反馈：模板套选择页展示的仍是旧样张，用户第一眼看到的就是旧观感——样张不换，感知不会变。
