# htmlppt 工具说明

> **一句话**：把一份 PPTX 或 HTML 稿，在「可编辑 HTML」和「可编辑 PPTX」之间稳定地来回转换，
> 并给出可量化的质检结果——不用记仓库里四套脚本，只用一个 `htmlppt`。

这份说明面向“会用终端、但不写代码”的人。下面的示例假设你在仓库根目录执行
（工具本身支持任意目录，用绝对路径调用即可）；把 `python3 cli/htmlppt.py` 当成 `htmlppt` 即可。

```bash
# 先确认环境（只读检查，不改任何文件）
python3 cli/htmlppt.py doctor
```

如果你经常用，可以加一个别名（只对当前终端窗口有效）：

```bash
alias htmlppt='python3 "/Users/an/Desktop/Atlas/PPT/HTML -ppt/cli/htmlppt.py"'
htmlppt doctor
```

## 1. 它能做什么：三件技能 + 一个闭环

```
        ┌──────────────────────── 提取 extract ────────────────────────┐
PPTX ──▶│ 原生对象 → 语义 HTML；图片抽取/内嵌；每个对象带 data-pptx-id  │──▶ deck.html
        └───────────────────────────────────────────────────────────────┘
                                                                  │
        ┌──────────────────────── 生成 build ──────────────────────────┐
HTML ──▶│ Chrome 量布局 → 原生 PPTX（文本/形状/图片/表格/渐变）        │──▶ deck.pptx
        └───────────────────────────────────────────────────────────────┘
                                                                  │
        ┌──────────────────────── 质检 verify ─────────────────────────┐
两者 ──▶│ LibreOffice 回渲 PPTX + Chrome 截 HTML，逐页像素 MAE          │──▶ verify.json
        └───────────────────────────────────────────────────────────────┘
                                                                  │
        ┌──────────────────────── 闭环 stack ──────────────────────────┐
PPTX ──▶│ extract → build → verify，一条命令跑完，任一步失败即停       │──▶ 三阶段产物
        └───────────────────────────────────────────────────────────────┘
```

| 技能 | 命令 | 输入 | 你得到 | 适合什么时候用 |
|---|---|---|---|---|
| 提取 | `extract` | `.pptx` | `deck.html` + `assets/` + `map.json` | 想在浏览器里改稿、换图、换文案 |
| 生成 | `build` | `.html` | `deck.pptx` + `metrics.json` + 对比图 | 想把 HTML 稿交付成可编辑 PPT |
| 入口体检 | `lint` | `.html` | 13 条规则报告（error/warning/info） | 转换前先排雷 |
| 质检 | `verify` | `.pptx` + `.html` | `verify.json` + `compare.png` | 交付前确认“转完还像不像” |
| 换图 | `slots` / `replace` | 提取产物 | 替换后的 HTML + 备份 | 想换照片/换页面背景 |
| 闭环 | `stack` | `.pptx` | 以上全部 | 第一次拿到一份稿，想全流程自检 |
| 契约 | `describe` | `国金模板.potx` | `contracts/describe.json` + 24 份 `layout.md` + `deck` 清单 | 想知道模板有哪些槽位/容量/主题，或给 agent 读 |
| 基准 | `bench` | 已有评测结果 | 引擎矩阵表 | 想知道“哪个引擎在哪项更强” |

## 2. 五个最常用的命令

### ⓪ `slots` / `replace`：换图不用改代码

```bash
# 列出所有可替换的内容图槽位（哪一页、多大、原图路径）
python3 cli/htmlppt.py slots out/deck-html

# 换一张内容图（原图自动备份到 assets/_originals/）
python3 cli/htmlppt.py replace out/deck-html --slot img-6-1 --image 新照片.jpg

# 换整页背景
python3 cli/htmlppt.py replace out/deck-html --background-slide 6 --image 新背景.png

# 改完重新生成可编辑 PPT
python3 cli/htmlppt.py build out/deck-html/deck.html -o out/deck-html/rebuild
```

> 说明：装饰图（logo/图标/页眉条）**不会**出现在槽位列表里——它们属于背景组件，保留原样。

### ⓪½ `lint`：转换前先排雷（Anthropic 方法论）

```bash
python3 cli/htmlppt.py lint deck.html          # 人类可读
python3 cli/htmlppt.py lint deck.html --json   # 给 CI / agent
python3 cli/htmlppt.py lint deck.html --strict # warning 也算失败
```

一次报全 13 类问题（尺寸不符、文本被裁、手打 bullet、vw/rem、滤镜、未知字体…），
带精确测量：`文本被裁：内容 96px > 框 40px`。转换管线第 0 步会自动跑它。

### ① `doctor`：先体检，别急着转

```bash
python3 cli/htmlppt.py doctor
```

会检查 python / node / soffice / chrome / pdftoppm / fc-match，以及 PingFang SC、Noto Sans SC、
Songti SC、Arial、Helvetica Neue、Inter 六个关键字体。看到 `✓ 必需工具齐全` 就可以开始。
缺工具时退出码是 `1`；缺字体只是 ⚠，仍可继续，但回渲 MAE 可能偏高。

### ② `extract`：把 PPTX 拆成可编辑 HTML

```bash
python3 cli/htmlppt.py extract 我的稿.pptx -o out/我的稿-html
```

打开 `out/我的稿-html/deck.html` 就能在浏览器里看到稿子。默认图片全部内嵌，**单个 HTML 文件**
即可分享；如果希望 HTML 保持小巧、图片放 `assets/`，加 `--no-embed`（这时 HTML 和 `assets/`
必须一起移动）。

产物里的 `map.json` 是“对象地图”：每个 PPT 元素对应 HTML 里的 `data-pptx-id`，
以后要“换第 3 页那张图”时，按 id 定位，不要用字符串替换。

### ③ `build`：把 HTML 变成可编辑 PPTX

```bash
python3 cli/htmlppt.py build out/我的稿-html/deck.html
```

默认输出到 HTML 同目录的 `htmlppt-out/`；想指定位置就加 `-o out/交付`。
命令结束会打印 `gates 12/12 · PASS` 这样的摘要。**不要只看“有没有生成文件”**：
如果 gates 没过，文件可能能打开，但文字丢了、整页变成一张图，交付出去就是事故。

### ④ `verify`：交付前的“像不像”体检

```bash
python3 cli/htmlppt.py verify \
  --pptx 我的稿.pptx \
  --html out/我的稿-html/deck.html \
  -o out/我的稿-verify
```

会得到一张逐页表：

```
页  MAE    diff>16%  diff>48%
1   7.66   5.05      3.76
2   3.99   3.83      2.46
...
合计  5 页 · 平均 MAE 6.31 · >16 5.42% · >48 3.89%
```

- **MAE**：平均像素差，越低越像。经验上 `<10` 很稳，`10–20` 可接受，`>30` 要逐页看。
- **diff>16%**：肉眼能看出差异的面积占比；比 MAE 更能反映“哪一页花了”。
- `compare.png` 是 HTML / PPTX / 差异三列拼版，一眼定位问题页。

### ⑤ `stack`：一条命令跑完闭环

```bash
python3 cli/htmlppt.py stack 我的稿.pptx -o out/我的稿-闭环
```

依次执行 extract → build → verify。任何一步失败就停在那一步，并保留已完成产物；
最后一行会给出“页数 / 对象数 / gates / 平均 MAE / 字符覆盖率”的总账。

> 附加：`python3 cli/htmlppt.py bench --quick` 可以看 8 个引擎的横向对比。
> 它只读已有评测结果，不会重跑、也不会改 `bench/`。

## 3. 结果怎么读（三个数字）

| 指标 | 在哪看 | 好结果 | 说明 |
|---|---|---|---|
| **gates** | build 摘要 / `metrics.json` | `12/12 PASS` | 硬门槛：文件能开、页数对、1280×720、文字覆盖 ≥90%、无整页大图、zip 全压缩等 |
| **字符覆盖率** | build 摘要 / `metrics.json` | `100%` | PPTX 里的非空白字符 / HTML 里的非空白字符；掉了字会直接反映 |
| **MAE** | verify 表 / `verify.json` | 越低越好 | LibreOffice 回渲 vs Chrome 截图；只用于横向比较，不等于 PowerPoint 的绝对效果 |

另外看两个“结构信号”：

- `p:pic` 很高、`a:t` 很低：文字可能被拍成了图，改不了。
- `lossy > 0`：extract 时有对象无法原生表达，去 `map.json` 的 `lossy` 清单看具体是哪页哪个对象。

## 4. 常见报错与处理

| 你会看到 | 原因 | 怎么办 |
|---|---|---|
| `python3: command not found` | 没装 Python 或不在 PATH | 装 Python 3.12；或把命令里的 `python3` 换成实际路径 |
| `No module named 'pptx'` / `PIL` / `numpy` | 当前 Python 不是仓库约定的环境 | `export HTMLPPT_PYTHON="/Users/an/Desktop/Atlas/PPT/PPT 复刻/.venv/bin/python"` 后重试 |
| `chrome ... not found` / Playwright 启动失败 | 没装 Chrome | 装 Google Chrome；`doctor` 应显示 chrome ✓ |
| `verify 未比对到任何页面` / 合计 0 页 | LibreOffice 配置目录被另一个 soffice 占用 | 关掉正在运行的 LibreOffice，再跑一次；CLI 已会自动重试 3 次 |
| `BUILD FAILED ... noFullPagePicture` | 原稿把整页背景做成了图片，转回来仍是整页图 | 这是保真结果，不是 bug；换非整页图原稿，或接受该 gate 失败 |
| `gates 11/12` / 某个 gate `false` | 构建有硬伤 | 打开 `htmlppt-out/metrics.json` 看失败键；**不要直接交付** |
| `node: SyntaxError: missing ) after argument list` | `prototype/` 正在被编辑，文件处于半保存状态 | 等编辑完成；用 `node --check prototype/src/measure.mjs` 确认；不要自己改 `prototype/` |
| 路径里有空格导致报错 | 路径没加引号 | 整个路径用双引号包起来，如 `"HTML -ppt/我的稿.pptx"` |
| `Permission denied` | 输出目录不可写 | 换一个你有写权限的 `-o` 目录 |

### 一条排查顺序

```bash
python3 cli/htmlppt.py doctor                 # 1. 环境
python3 cli/htmlppt.py extract 稿.pptx -o out/x   # 2. 提取是否成功
python3 cli/htmlppt.py build out/x/deck.html      # 3. gates 是否全过
python3 cli/htmlppt.py verify --pptx 稿.pptx --html out/x/deck.html -o out/v  # 4. MAE
```

## 5. 边界与约定

- `htmlppt` **只调用** `pptx2html/`、`prototype/`、`bench/`，不修改它们；所有输出都写到你用 `-o` 指定的目录。
- 不给 `-o` 时的默认位置：`extract` → `<pptx目录>/<名字>-html`；`build` → `<html目录>/htmlppt-out`；
  `verify` → `<html目录>/verify`；`stack` → `<pptx目录>/<名字>-stack`。
- 所有命令都支持 `--json`，stdout 只有 JSON；脚本里请按退出码判断：`0` 成功、`1` 失败、`2` 用法错误。
- 详细字段、实现调用关系、本次真实跑通记录见 [cli/README.md](cli/README.md)。
- 转换管线本身的设计与限制见仓库根的 [技术方案-HTMLPPT-转换管线-v1.0.md](技术方案-HTMLPPT-转换管线-v1.0.md)
  和 [规范-HTMLPPT-HTML契约-v1.0.md](规范-HTMLPPT-HTML契约-v1.0.md)。
