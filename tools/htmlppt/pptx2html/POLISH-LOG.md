## 第 3 轮（2026-10-20）：拆包与颜色保真

### ① 媒体没有"原样拆出来"，而是重编码了

- **现象**：图片边缘发糊、颜色轻微偏移；抽取速度慢（20s+）。
- **根因**：`save_picture` 用 PIL 打开 → RGBA → 重采样到 2× 显示尺寸 → 存 PNG。等于每张图都重编码一次。
- **修法**：PPTX 就是 zip。按 `r:embed` 拿到 `ppt/media/imageN.png` 的原始部件，**直接写原始字节**；按 partname 去重（同一张图多处引用只存一份）；只有 `srcRect` 裁剪时才生成裁剪副本。
- **效果**：媒体 339 个 / 36MB；抽取 20s → 11s；图片零重编码。

### ② 「SVG 图 + PNG 回退」被当成了 2×2 灰块

- **现象**：P10 的显微镜/公文包/人物插图变成灰色方块；P1 右下二维码灰块。
- **根因**：这些图在 XML 里是 `<a:blip r:embed="..."><a:extLst><a:ext><asvg:svgBlip r:embed="..."/>`——真正的图是 **SVG**，PNG 只是 2×2 的兼容回退。python-pptx 的 `sh.image` 返回的是回退 PNG。
- **修法**：解析 `svgBlip` 扩展，取 SVG 关系部件，存 `assets/media/imageN.svg`，HTML 直接引用 SVG（浏览器可渲染，正向管线还能转成原生曲线）。
- **效果**：8 张 SVG 全部还原；P10 插图回来（36.5 → 26.5）。

### ③ 主题色修饰符（lumMod/lumOff/shade/tint）被忽略

- **现象**：P17 三张渐变卡整片偏蓝（原稿是近白浅蓝）；大量形状颜色偏深。
- **根因**：OOXML 里主题色常写成 `<a:srgbClr val="4BD1FB"><a:lumMod val="8000"/><a:lumOff val="92000"/></a:srgbClr>`，只取 `val` 会得到饱和度极高的原色。我们只读了 `val`。
- **修法**：新增 `resolve_color_el()`：解析 srgbClr/schemeClr/sysClr + HSL 空间应用 lumMod/lumOff/shade/tint/satMod；填充、渐变、文字、描边全部走它。
- **效果**：**P17 73.4 → 21.5**，整体 19.75 → 16.89。

### ④ 连接线被画成"大色块"

- **现象**：P5 地图上出现一块 200×200 的深蓝色块。
- **根因**：`MSO_SHAPE_TYPE.LINE` 分支把包围盒高度当 `border-width` 画：`border:108px solid #0552D1`，于是整块变实心蓝。
- **修法**：改用 SVG `<line>`：按 `a:ln@w` 取真实线宽、按 xfrm 的 flipH/flipV 决定端点方向、支持虚线。
- **效果**：**P5 22.7 → 12.8**，整体 16.89 → 15.78。

### ⑤ 组合内的自由曲线坐标没有跟随组变换

- **现象**：P10 中间那块青色椭圆（"任意多边形"）消失，跑到了画布左上角 0.8px 处。
- **根因**：自由曲线分支用的是 `shape_common_style(sh)`（原始子坐标），没传组变换矩阵 `tx`。
- **修法**：改用已带 `tx` 的 `base`。
- **效果**：青色椭圆归位（P10 继续下降）。

### ⑥ 背景装饰判定过宽，把整组合并进背景层

- **现象**：P10 的 Venn 组合被压到背景层，插图被黄圈盖住。
- **根因**：`background-decoration` 判定只看"面积 ≥50% + 无文字"，组合（group）的 `has_text_frame` 恒为 False，被误判。
- **修法**：组合不参与；面积阈值提到 60%；只允许最底层（idx ≤ 1）。
- **效果**：Venn 插图回到内容层，层级正确。
